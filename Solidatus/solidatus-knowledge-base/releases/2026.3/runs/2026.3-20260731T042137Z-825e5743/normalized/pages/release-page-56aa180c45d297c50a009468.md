# Model structure

The Solidatus Databricks Connector represents Databricks metadata and lineage in a multi-layered model structure. Each layer corresponds to a key aspect of the Databricks data landscape, allowing users to visualize sources, schemas, tables, jobs, and data flows.

The main layers are:

* Each catalog has its own layer (see [Catalog Layer](#catalog-layer))
* [Jobs Layer (Optional)](#jobs-layer-optional)

## Note on Extraction

> The connector builds the model by extracting metadata and lineage from Databricks Unity Catalog and, optionally, Databricks jobs. Only the catalogs, schemas, and tables relevant to the lineage and configuration will be included in the model.

## Catalog Layer

Each catalog in your Databricks Unity Catalog environment is represented as a separate layer in the Solidatus model. This allows you to clearly distinguish and analyze the structure and lineage within each catalog.

For each catalog:

* An **Object** represents a schema within the catalog.
* Each **Group** in the schema object represents a table.
* Each **Attribute** in the table group represents a column.
  * Each column attribute has a `SOL.UID` which can be used for **Auto Mapping**.

### Entity Naming

* Objects are named after the schema (from Unity Catalog).
* Groups are named after the table.
* Attributes are named after the column.

## Jobs Layer (Optional)

If enabled, the Jobs layer represents Databricks jobs and their relationships to tables. This layer shows how jobs read from and write to tables, providing operational lineage.

* An **Object** represents a Databricks job.
* Each **Group** in the job object represents either sources or targets (i.e., the tables or columns read or written by the job, depending on the level of lineage detail available).
* Each **Attribute** in the group typically represents a column processed by the job. If only table-level lineage is available, the attribute may represent the table as a whole.

### Entity Naming

* Jobs are named after their Databricks job name.
* Source/target groups are named for their role (e.g., "Sources", "Targets").
* Attributes are named after the columns they process.

## Transitions (Lineage)

Transitions represent data flows between columns, tables, and jobs. If the jobs layer is enabled, transitions will show the flow through jobs; otherwise, direct table-to-table lineage is shown.

## Limitations

* Only assets registered in Unity Catalog (or as external metadata) are included.
* Notebooks and non-Unity Catalog assets are not included.
