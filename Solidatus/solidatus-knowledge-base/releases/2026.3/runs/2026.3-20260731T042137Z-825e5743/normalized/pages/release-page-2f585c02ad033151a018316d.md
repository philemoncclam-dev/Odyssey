# Model roles and permissions

Not every user is equal when we’re talking about using Solidatus models. A model owner is in complete control over which users and/or [groups](/models/share-and-collaborate/groups) have access to the model, and what actions they can perform, via four unique model roles: Owner, Author, Approver, and Viewer.

{% hint style="success" %}
The same general points apply to managing access to [Data Domains](/data-domains/build-data-domains/edit-data-domains#data-domain-roles-and-permissions), [Agents](/connectors/connectors-overview/users-and-tokens#agent-roles), and [Jobs](/connectors/connectors-overview/users-and-tokens#job-roles), but the role types and their permissions in these contexts are different.

Please view the pages for each feature for specific role types and permissions.
{% endhint %}

## Share a model and assign roles

There are a number of ways to share a model with other registered Solidatus users or groups and to set their model roles:

* Within the [Model Overview](/the-user-interface/models-ui/model-overview#permissions), use the *Permissions* section of the *Settings* tab.
* Within the [Model Overview](/the-user-interface/models-ui/model-overview#summary-tab), use the `PEOPLE` section on the `Summary` page.
* Within the [Model Overview](/the-user-interface/models-ui/model-overview#actions-menu), click the `ACTIONS` button in the top right and select `Manage Sharing`.

## Permissions for each model role

Each role permits a unique set of actions to be performed relative to a given model. The following table lists the permissions available for each model role.

{% hint style="warning" %}
Remember that a user registered with a Consumer (read-only) or Practitioner licence **will not** be able to perform many actions permitted by Owner, Author, Approver, or Viewer roles, even if they are assigned these roles on a model.
{% endhint %}

| **Action**                                          | **Owner** | **Author** | **Approver** | **Viewer** |
| --------------------------------------------------- | --------- | ---------- | ------------ | ---------- |
| Edit model settings and permissions                 | X         |            |              |            |
| Delete the model                                    | X         |            |              |            |
| Merge Pull Request / task / model import update     | X         | X          |              |            |
| Create, edit, and assign tasks                      | X         | X          |              |            |
| Edit the model directly (without creating a Fork)   | X         | X          |              |            |
| Approve activities                                  | X         | X          | X            |            |
| View model and model history                        | X         | X          | X            | X          |
| View tasks/Pull Requests/model import updates       | X         | X          | X            | X          |
| Comment on tasks/Pull Requests/model import updates | X         | X          | X            | X          |
| Create and edit a model Fork                        | X         | X          | X            | X          |
| Submit Pull Request from Fork                       | X         | X          | X            | X          |
| Export the model                                    | X         | X          | X            | X          |

{% hint style="warning" %}
Dashboards, Agents, and Jobs have their own specific roles - see [Data Domain Roles](/data-domains/build-data-domains/edit-data-domains#data-domain-roles-and-permissions), [Agent Roles](/connectors/connectors-overview/users-and-tokens#agent-roles), and [Job Roles](/connectors/connectors-overview/users-and-tokens#job-roles).
{% endhint %}

## Useful facts about model roles

* The user that creates a model is automatically assigned the Owner role on that model, and, therefore, can share the model with other users or groups.
* More than one user or group is allowed to own a model, and any Owner can assign and remove other owners (as long as at least one owner remains).
* An individual user may have been assigned a role for a model directly and/or inherited a role via their membership of one or more groups.
* When checking what role a user has on a model, Solidatus will take the union of all the capabilities provided to them, whether assigned directly to that user or to one or more groups that the user is a member of.

The Model Overview provides a checkbox called `Show inherited roles` so you can see all roles each user has on the model.
