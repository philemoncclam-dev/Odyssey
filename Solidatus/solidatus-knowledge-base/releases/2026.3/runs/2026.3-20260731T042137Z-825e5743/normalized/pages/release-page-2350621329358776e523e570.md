# Activities

Solidatus provides a single workflow for managing collaboration among users, facilitating effective development of Models. Solidatus also allows any user with visibility of the Model to start a discussion about the Model, ask a question, or just make a comment.

All of the above are referred to as **Activities**. A single lifecycle applies to all Activities, with variations according to the type of Activity. Depending on the Model settings, changes made by an Activity may be subject to approval. The Model settings may also allow the changes to be [automatically merged](/models/share-and-collaborate/activities-and-activity-types/auto-merge) into the Model, either as soon as they are proposed or once they have been approved.

The [Activities tab](/models/share-and-collaborate/activities-and-activity-types/activities) in the Model Overview allows a user to see at-a-glance all in-progress updates for a Model, and use this to manage workflow for the Model. A user can also manage their personal workflow via [their own list of Activities](/the-user-interface/models-ui/activities-interface#the-my-activities-list).

{% hint style="success" %}
The Activities tab does not display information about model changes made using the standard editing and saving workflow. You can see this information (and more) listed on the `Revisions` tab.
{% endhint %}

The [model list](/the-user-interface/models-ui/model-browser#list-of-models) in the Model Browser will include icons that provide information to a user about Activities they need to be aware of.

In the Model Browser, flag icons indicate the number of unresolved activities there are for a Model (not all of which require action by the current user). If you wish to see only the activities you personally need to be concerned with, take a look at [your own list of activities](/the-user-interface/models-ui/activities-interface#the-my-activities-list).

If approvals are required for an activity there will be additional information available. See approvals for more information.

### Approvals and auto-merge

Model owners can choose to enable the [approvals workflow](/models/share-and-collaborate/approvals-workflow) for tasks, pull requests, import updates, and parent model changes activities.

If a Model owner has enabled [auto-merge](/models/share-and-collaborate/activities-and-activity-types/auto-merge) for a type of Activity, the proposed changes will be automatically merged into the Model to create a new revision, subject to the [approvals workflow](/models/share-and-collaborate/approvals-workflow), if that has been enabled.

### The activity page

Every Activity has a common page (accessed via [Activities Interface](/the-user-interface/models-ui/activities-interface) or the [Activities](/the-user-interface/models-ui/model-overview#activities-tab) tab on the Model Overview) where the activity can be progressed, tagged, and a thread of comments can be made. The actions available will depend on the user’s permissions for the Model and Activity, and on the current state of the Activity.

The example below shows the Activity page for an Import update that has been submitted. We can tell that approvals are required for such changes in this Model, that the current user can approve or reject the changes, and that *Demo User2* has been invited to approve the Activity.

<figure><figcaption><p>The Activity page for an Import update</p></figcaption></figure>

{% hint style="success" %}
When you click on the `Approve` or `Reject` buttons, remember to leave a comment in the dialogue that pops up, especially if you’re rejecting an Activity.
{% endhint %}

#### Activities requiring approval

If the [Activity settings](/the-user-interface/models-ui/model-overview#settings-tab) for a Model require it, the [Activity page](#the-activity-page) will display `Approve` and `Reject` buttons for users that are able to approve the Activity.

If you’ve been asked to [approve an Activity](/models/share-and-collaborate/approvals-workflow), you could just click on the `Approve` or `Reject` buttons in the Activity page, but you shouldn’t do that until you’ve actually seen the changes. Click the `View changes` or `Visual Merge` button to review the changes and use the `Approve` or `Reject` buttons in the [diffing dialogue](/models/build-and-edit-models/diff-mode) to record your decision.

Providing a comment when you approve or reject an Activity is a good routine to establish, especially when rejecting an Activity.

<figure><figcaption><p>Explain your reasons for approving or rejecting the changes</p></figcaption></figure>

{% hint style="success" %}
There may be other users that can approve or reject these changes (every Model owner is able to do this) - the Activity page only lists those users who were specially **invited** to take part. If you need to see a list of every user that can approve a change, look at the list of Model owners and authors on the *Permissions* section of the [Settings tab](/the-user-interface/models-ui/model-overview#settings-tab) on the Model Overview.
{% endhint %}

See [Questions, Discussions, etc.](/models/share-and-collaborate/activities-and-activity-types/questions-comments-discussions-etc.) for an example of a trail of comments.

{% hint style="warning" %}
It only takes one user to reject an Activity, and it doesn’t matter if that user is a model Owner or an invited Approver.
{% endhint %}
