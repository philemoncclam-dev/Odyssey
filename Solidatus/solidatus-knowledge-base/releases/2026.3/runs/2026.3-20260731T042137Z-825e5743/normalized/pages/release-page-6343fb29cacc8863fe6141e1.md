# Models main

This section contains comprehensive information about Solidatus models, from modeling concepts and terminology to all functionality involved in building and editing models, exploring and analysing models, version control, sharing models, and collaborating with others on model work.

{% hint style="success" %}
For more technical information on building models with the help of Connectors or the API, see the [Connectors](/connectors/connectors-overview) page and [The Solidatus API](https://github.com/solidatus/Solidatus-docs-gitbook/blob/stable/solidatus-core/models/broken-reference/README.md) sections.
{% endhint %}

At the most basic level, a Solidatus model is an explorable map of connections between hierarchically nested model entities. Models help you visualise and analyse complex data infrastructure, but they also store information and can be used to query, document, and assess the target systems and reference content that a model represents.

{% hint style="success" %}
While Solidatus models can be used to represent nearly anything, they are designed specifically for capturing **data lineage** and for documenting technical lineage in relation to semantic frameworks like governance structures, business glossaries, external regulations, and internal policies.
{% endhint %}

Models serve as the foundation of the Solidatus platform, powering enterprise-wide Data Maps and Data Domains that enable you to visualise, search, browse, query, and quantitatively analyze across models. All information in Data Domains originates from models published to those domains.
