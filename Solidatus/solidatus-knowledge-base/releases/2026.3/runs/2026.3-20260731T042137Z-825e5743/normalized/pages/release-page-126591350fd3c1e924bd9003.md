# Export and reimport model content

It can be convenient to edit a model by exporting to an external file, editing the external file, and then reimporting edited content.

For example, if bulk editing entity relationships, Transitions, or properties, you can export to a spreadsheet, edit content in the spreadsheet, and then reimport the tabular data.

Exporting and reimporting can be used with any of the export formats (CSV, JSON, YAML), but since it is likely to be particularly useful in tabular, this page focuses on the CSV format.

Scenarios in which exporting and reimporting can be especially useful are:

* Adding or updating properties in bulk
* Adding Transitions in bulk
* Adding or updating Reference relationships in bulk
* Updating relationships from an old reference model to a new one

## Export a Model for Reimporting

To export a model in preparation for reimporting:

* Click `Export` in the Model Viewer toolbar
* Select CSV as the export format
* Select the parts of the model to export
* Choose a column setting: **Default** or **Custom**
* Click `NEXT` to export the chosen data as a CSV file

The export dialog provides a number of entity export options for CSV, XML, and YAML exports. Hover the mouse over each option to see tooltips in the user interface.

By default, the export will include every entity in the model, but this can be modified using the options in the export dialog.

See [Export Model Content](/models/explore-and-analyse-models/export-model-content) for more information on the export options available in the dialog.

{% hint style="success" %}
You can also export and reimport using [Grid Reports](/models/explore-and-analyse-models/grid-reports), but the principle is the same as for the **Custom** export option described below: if you want to reimport, select columns and column arrangements for your export that match a valid import format.
{% endhint %}

## Default exports

The **Default** export format is the same as the format on the `import-full.xlsx` [template](/get-started/import-model-content/import-from-spreadsheets#full-import-format).

The Default format includes the following columns: `ID`, `TYPE`, `PARENT`, `NAME`, `SOURCE`, `TARGET`, `REFERENCE_MODEL_ID`, `TERM_ID`, `LABEL`, `PROPERTIES:`, followed by headings for properties of entities defined in the `ID` column.

Since the **Default** format is valid for importing, you can reimport without modifying columns or column arrangements.

{% hint style="success" %}
Exports contain a separate row for each Reference relationship an entity has, so entities will be listed as many times as the number of relationships they have. These means duplicate information can be contained in multiple rows where only the values in the Reference relationship columns differ.
{% endhint %}

The `ID` column is populated by entity IDs of entities in the model, and `SOURCE` and `TARGET` columns define Transitions using the entity IDs of the source and target entities.

You can edit any values in the exported CSV (apart from the entity IDs, which are used to match imported data to an existing entity) and then reimport using the tabular importer.

## Custom Exports

The **Custom** export option enables you to choose column headings to include in the export CSV file.

<figure><figcaption></figcaption></figure>

If you are aiming to reimport the CSV without modifying columns, it is important to select columns that are valid for importing. The easiest way to ensure your custom export can be reimported is to select and arrange columns in a way that matches one of our [downloadable import templates](/get-started/import-model-content/import-from-spreadsheets#downloadable-import-templates).

{% hint style="success" %}
If you are planning to reimport, it is best to choose either `PATH` or `ID` as the first column in which the entity occupying each row is defined. You can then choose additional columns based on what you want to edit in the model.
{% endhint %}

For example, you can choose `PATH`, `SOURCE_PATH`, and `TARGET_PATH` to export all entities, including Transitions. You can add relationships using the three columns needed to define a relationship: `REFERENCE_MODEL_ID`, `TERM_ID` (or `TERM_PATH`), and `LABEL`.

To export properties, add the `PROPERTIES:` and then type in the names of properties you wish to export, separated by commas.

Defining properties after an empty column with the heading `PROPERTIES:` is not the only format recognized by the importer. You can also import properties using column headings in the format `PROPERTY:property_key`, and the exporter allows you to export properties in this column format.

<figure><figcaption></figcaption></figure>

So, another way to export properties that you want to reimport is to select the `Property:property_key` column and replace the `property_key` with the name of the property you wish to export.

<figure><figcaption></figcaption></figure>

{% hint style="success" %}
If you export entity paths, special characters in entity names – such as `/`, `[` , or `]` – are escaped by a `\` in front of the special character.

As a result, entities with special characters in their names can be exported and reimported directly without modifying them in the CSV file.

For example, the exported path of an Object named `Table2/ColumnA` in a Layer name `Table2` is `/Table2/Table2\/ColumnA`.
{% endhint %}
