# Solidatus 5.2

We are pleased to announce the general availability of Solidatus release 5.2.

Solidatus release 5.2 introduces eight distinct property types, each of which has its own validation rules and visualisation, so properties are easier to set consistently and within validation rules. The query language has been enhanced to enable Display Rules and Filters to assess the validity of properties.

Upgrading to release 5.2 will **not** affect any existing properties. You can manually change the property types from the default *Text* type, or use the new [Infer Types button](/models/build-and-edit-models/add-and-edit-properties#infer-property-types) in the Property Manager to infer the property types for all text properties in a Model.

The Sidebar in the Model Viewer has been enhanced to enable you to create and manage Reference Relationships more easily, using the newly-merged *Properties and relationships* panel in the *Inspector* tab.

## Property types

Prior to release 5.2, all properties were treated in the same way, as a chunk of text that might match a pattern (such as *True* or *False* or a valid date) that could be used to affect how it is displayed. There was no validation, and it wasn’t possible to add multiple, individual values to a property.

That has all changed, with the introduction of [Property Types](/models/understand-solidatus-models/understand-properties/property-types), which provides

> * eight distinct types of property
> * validation of property values according to the property type
> * the ability to select multiple values for a single property
> * improved visualisation of properties.

Solidatus provides eight different property types (the default type is `Text`), each of which has its own validation rules and visualisation. Invalid properties are highlighted in the `Properties and Relationships` panel in the [Model Viewer Sidebar](/the-user-interface/models-ui/model-viewer/model-viewer-sidebar) and in the [Property Manager](/models/build-and-edit-models/add-and-edit-properties#the-property-manager).

Assigning property types helps users to enter data more quickly and easily in a standardised way to improve metadata quality.

**Inferring property types**

Upgrading to release 5.2 will **not** affect any existing properties. You can manually change the property types from the default *Text* type, or use the new [Infer Types button](/models/build-and-edit-models/add-and-edit-properties#infer-property-types) in the Property Manager to infer the property types for all text properties in a Model.

Properties can still be created in the `Properties and Relationships` section in the [Model Viewer Sidebar](/the-user-interface/models-ui/model-viewer/model-viewer-sidebar) and in the [Property Manager](/models/build-and-edit-models/add-and-edit-properties#the-property-manager). If a property is created in the `Inspector` tab, the property type is inferred from the first value you provide.

**Property visualisation**

Each type of property has its own visualisation rules, which you can read about at [Characteristics of property types](/models/understand-solidatus-models/understand-properties/property-types).

**Sidebar changes**

We have merged the Properties and Relationships Sidebar panels into one single panel.

**Query language changes**

Two new predicates allow you to assess the validity of property values in a query.

> * `hasInvalidProperty()` will match all entities that have at least one invalid property
> * `isValidProperty('property_name'))` will match an entity if the *property\_name* property is valid

## Creating and managing reference relationships

Previously, the *Inspector* tab only allowed you to *view* existing Reference Relationships for your current selection (and to access the Reference Model, but not the related Term) - you needed to use the *Reference Models* tab to actually create or manage Relationships.

Now the *Inspector* tab provides new capabilities for creating and editing relationships, as well as providing access to the Term itself and the usage features that the Reference Model tab provides.

## Other changes

**Redesigned Activity Settings page on the Model Overview**

The [Activity Settings](/models/share-and-collaborate/activities-and-activity-types/activities#the-activity-page) page has been simplified to show a textual description of the current settings for each type of Activity and a `Manage` button for editing the settings for a type of Activity.

**Merging an activity adds a timeline entry with the revision text**

When you merge an Activity you can provide a Revision description - this is now also recorded for the Activity itself, not just for the revision.
