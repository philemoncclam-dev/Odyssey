# Usage

### Usage

There are two ways to run the JDBC connector, Agent mode and Standalone mode. Standalone mode runs a singular instance of the Connector with supplied config and publishes the model. Agent mode sets up a Solidatus Agent to connect to the hosted Solidatus site that can receive and run JDBC jobs with unique configurations.

Configuration can also be set using a `{}.yml` file as presented in `fullSample.yml` and `template.yml`. Alternatively the configuration can be passed in as command line parameters to the JDBC Connector JAR file. If using both methods the command line arguments will overwrite the configuration `.yml` file. See the [Configuration Options](/connectors/connector-specific-documentation/solidatus-jdbc-connectors/configuration) section for more detail.

### Running the connector with docker

The connector can be run via `docker-compose` where an example of a `docker-compose.yml` can be found. Then execute `docker-compose up -d`.

To run the container using docker, run the command to execute would be `docker run -d -v data:/data --name <name_of_container> <tag_name_of_image> [flags]`.

### Bundled JDBC supported drivers

| driver       | description                                   |
| ------------ | --------------------------------------------- |
| `mysql`      | JDBC driver for MySql                         |
| `oracle12`   | JDBC driver for Oracle                        |
| `sqlserver`  | JDBC driver for Microsoft SQL Server          |
| `cassandra`  | JDBC driver for Cassandra                     |
| `sybaseASE`  | JDBC driver for Sybase ASE                    |
| `sybaseIQ`   | JDBC driver for Sybase IQ                     |
| `snowflake`  | JDBC driver for Snowflake                     |
| `redshift`   | JDBC driver for Redshift                      |
| `postgresql` | JDBC driver for PostgreSQL                    |
| `custom`     | A user supplied JDBC driver via the classpath |

### Advanced use with custom driver config

It is possible to use the tool with any JDBC driver that supports an implementation of the `java.sql.DatabaseMetaData` interface.

To do so we need to change the command line a little to take advantage of some Spring Boot features.

```bash
java -cp ./solidatus-jdbc-connectors.jar:PATH_TO_JDBC_DRIVER/DRIVER.jar \
-Dloader.main=com.solidatus.app.Main org.springframework.boot.loader.launch.PropertiesLauncher \
--spring.profiles.active="standalone" \
--solidatus.jdbc.driver=custom \
--solidatus.jdbc.driver-class=com.microsoft.sqlserver.jdbc.SQLServerDriver \
--solidatus.jdbc.url="jdbc:sqlserver://localhost:1433;database=AdventureWorks" \
--solidatus.jdbc.username=JDBC_CONNECTION_USERNAME \
--solidatus.jdbc.password=JDBC_CONNECTION_PASSWORD \
--solidatus.jdbc.schema-pattern=COMMA_SEPARATED_SCHEMA_NAMES \
--solidatus.api.host=$SOLIDATUS_HOST \
--solidatus.api.token=$SOLIDATUS_TOKEN \
--solidatus.api.model-name="Solidatus Model Name"
```

The above command adds a custom JDBC driver class `DRIVER.jar` to the classpath.

| property                                                                     | description                                                  |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `--solidatus.jdbc.driver=custom`                                             | tells the application to use the custom driver configuration |
| `--solidatus.jdbc.driver-class=com.microsoft.sqlserver.jdbc.SQLServerDriver` | the JDBC driver class to use                                 |

Please contact Solidatus to see if you are licensed to use this feature.
