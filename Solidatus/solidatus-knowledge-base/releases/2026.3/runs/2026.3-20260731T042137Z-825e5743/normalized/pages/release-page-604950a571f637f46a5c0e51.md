# Domain query language reference

This page serves as a comprehensive reference for the domain query language (DQL).

It includes a user interface guide, a detailed reference on available predicates and query syntax, and examples to help you construct effective queries.

Note that Solidatus has two query languages: the **domain query language** explained on this page and the **model query language** explained in the [model query language reference](/models/explore-and-analyse-models/model-query-language).

## Introduction

The DQL provides a more precise, fine-grained way to find what you are looking for in a Data Domain.

A **DQL query** is a logical statement that returns the items for which the statement evaluates to **true** within a Data Domain.

The DQL is designed to be easy to use and learn, with intuitive, readable syntax. It supports a variety of operators and predicates, which can be combined to create complex, precise query conditions.

Queries can return items based on high-level or fine-grained criteria, including names, entity types, properties and values, reference relationships, hierarchy, or lineage connections.

Queries can be used in a variety of areas within Data Domains:

* **Data domain search** — Return all entries in a domain that match the query conditions.
* **Analytics reports** — Count all matching entries in a domain that match the query conditions.
* **Data Map display rules** — Tag all entries in a Data Map that match the query conditions.

## The query helper

The **QUERY** button on the right-hand side of the search bar opens the domain query helper.

<figure><figcaption><p>Select the QUERY button in the search bar to open the Query Helper</p></figcaption></figure>

The query helper contains example queries organized by category that demonstrate correct syntax, and you can click them to enter them into the search bar.

Replace the example query terms with your own terms, then execute the query by pressing **ENTER** on your keyboard. You can select multiple examples and logical operators to build more complex queries that combine predicates.

<figure><figcaption><p>Open the Query Helper to find examples that you can fill in with your own search terms</p></figcaption></figure>

Queries are organised along the left-hand side by the characteristics targeted by a class of predicates: `Entity`, `Property`, `Relationship`, `Model`, `Hierarchy`, `Trace`, and `Transition`.

Click a class along the left-hand side to view query examples in that class in the main window.

All available predicates in the domain query language are represented in the query helper; however, the examples are simple, single-predicate examples and you can use this reference for a better understanding of complex syntax and what is possible using the DQL.

<figure><figcaption></figcaption></figure>

For example, you can combine `Name=` with `Property: key=value` using the logical operator `And`:

`Name=CDE And Property:dataQuality=Pass`

This returns entities that have **both** an exact name and a property with a specific value.

{% hint style="success" %}
Even though the examples in the query helper provide quotation marks around query terms, these are only required if terms contain spaces or special characters.

For example, the property “Business Name” or the property value “Mortgage interest” require quotation marks to ensure correct processing, while Customer does not.
{% endhint %}

### Query colour-coding

When a query with valid syntax is entered in the search bar, colour-coding is used to confirm that the query is valid and to identify distinct query elements.

A green checkmark also appears on the right-hand side of the search bar when a valid query is entered. If you mean to enter a query and the syntax is not valid, the text appears plain.

<figure><figcaption></figcaption></figure>

* **Plain (no colour)** = Logical operators and second-order predicates
* **Blue** = First-order predicates
* **Purple** = The terms of your query

## Operators

The DQL includes comparison and logical operators that enable you to construct precise query conditions.

### **Comparison operators**

Comparison operators are needed with first-order predicates, such as `Name`, to specify a comparison condition on the entered value.

* `=` : Exactly equal to (case-sensitive)
* `~=` : Contains (see example below for "contains" logic)
* `!=` : Not equal to
* `<` : Less than
* `<=` : Less than or equal to
* `>` : Greater than
* `>=` : Greater than or equal to

{% hint style="success" %}
`Name~=CDE`

Contains matches entities named *CDE* (case-insensitive), and also entities where the substring *cde* appears as a discrete segment either:

* (a) delimited by non-alphanumeric characters or string boundaries (e.g. cdexyz, xyz\_cde\_abc) or
* (b) delimited by a change in letter casing relative to adjacent characters (e.g., edfCDEghe).
  {% endhint %}

### **Logical operators**

Logical operators are used when combining predicates to create more complex query conditions.

{% hint style="warning" %}
**Rules to keep in mind:**

* All logical operators are case-sensitive; they must start with a capital letter followed by lower-case.

* When no logical operator is provided between predicates, the condition is interpreted as `And`.
  {% endhint %}

* `And` : Combines conditions where all must be true

* `Or` : Combines conditions where at least one must be true

* `Not` : Negates a condition

{% hint style="success" %}
`Name=Customer And Property:dataQuality=Pass`

(equivalent to `Name=Customer Property:dataQuality=Pass`)

This retrieves all entities with the exact name “Customer” **and** the exact property “dataQuality” equal to “Pass”.
{% endhint %}

## Predicate notes and examples

### First-order predicates

* `Name=`

(Alias `Term=` when used inside `HasRelationship:` or `HasDirectRelationship:`)

*Notes: Can be used with* `=`, `~=`, `!=`*. Name string matching is case-insensitive. Double or single quotation marks required if name has more than one word.*

{% hint style="success" %}
`Name="Customer ID"`

Returns entities with the exact name *Customer ID*.

`HasRelationship: Term=CDE`

Returns entities related to the term named *CDE* or to descendants of the term named *CDE*.
{% endhint %}

***

* `EntityType=`

Type can be `Layer`, `Object`, `Group`, `Attribute`.

*Notes: Cannot be used with comparison operators* `~=` *and* `!=` *. Data Domains do not retrieve Transitions. Use commas to separate multiple query values.*

{% hint style="success" %}
`EntityType=Object, Attribute`

Returns all Objects or Attributes in the domain.
{% endhint %}

***

* `EntityId=`

Multiple entity IDs can be provided, separated by commas. Quotation marks around separate IDs are not necessary.

*Notes: Cannot be used with comparison operators* `~=` *and* `!=`. *Data Domains do not currently retrieve Transitions.*

{% hint style="warning" %}
Where can I find entity IDs?

You can find the IDs of entities in the underlying model data via an API request or by selecting them in the underlying model and looking at the Selection panel in the **INSPECTOR** tab.
{% endhint %}

{% hint style="success" %}
`EntityId=a2b55058-3e6e-43ee-a843-614613e9bdbe, 2dfb5055-76f3-4b79-afec-36ceb222cc95`

Returns the two entities with the provided IDs.
{% endhint %}

***

* `Property: key`

`Key` refers to the name of the property.

*Notes: Property string matching is case-insensitive. Can be used with all* [*property types*](/models/understand-solidatus-models/understand-properties/property-types)*.*

{% hint style="success" %}
`Property: "Business Name"`

Returns all entities that have the exact property “Business Name” with any value for the property.
{% endhint %}

***

* `Property: key=value`

`Key` refers to the name of the property, `value` refers to the property value.

*Notes: Can be used with all comparison operators. Text matching is case-insensitive. Double quotation marks only required when keys or values contain multiple words.*

To match values for multi-select property types, you must use the contains `~=` comparison operator. This matches entities with **any** of the provided values (separate multiple values with commas).

To match only entities with a specific combination of multi-select values, use the contains `~=` comparison operator and combine multiple property predicates using `And`. For example:

`Property: "multi"~="one" And Property: "multi"~="two" And Property: "multi"~="three"`

This query returns entities with the specific combination of values `one`, `two`, and `three` for the multi-select property `multi`.

{% hint style="success" %}
`Property: "Data Quality"=Pass`

Returns all entities that have the exact property *Data Quality* with an exact value *Pass*.
{% endhint %}

***

* `Model=`

Returns entities in the model with the provided name.

*Notes: Cannot be used with comparison operators `~=` and `!=`. Model name string matching is case-insensitive.*

{% hint style="success" %}
`Model="Mortgage Lending Sources to Reports"`

This returns all entities contained in the model with the exact name “Mortgage Lending Sources to Reports”.
{% endhint %}

***

* `ModelId=`

*Notes: Cannot be used with comparison operators* `~=` *and* `!=`.

{% hint style="success" %}
`ModelId=667bf339652d59b49703fb10`

Returns all entities contained in the model with the ID 667bf339652d59b49703fb10.
{% endhint %}

{% hint style="warning" %}
Where can I find the ID of a model?

The ID of a model is located at the end of the URL in your browser when you have the model open in either the Model Viewer or Model Overview.

For example, the URL `https://demo.solidatus.com/viewer/653645f3f325325382b7e551` shows a model ID of `653645f3f325325382b7e551`

You can copy the ID from the URL in your browser and paste it into a `ModelId` query.
{% endhint %}

***

* `NumTransitions=`

*Can be used with comparison operators* `=` , `<`, `<=`, `>`, *and* `>=`.

{% hint style="success" %}
`NumTransitions=5`

Returns entities with a total number of 5 transitions (incoming + outgoing).
{% endhint %}

***

* `NumIncoming=`

*Can be used with comparison operators* `=` , `<`, `<=`, `>`, *and* `>=`.

{% hint style="success" %}
`NumIncoming>5`

Returns entities with more than 5 incoming transitions.
{% endhint %}

***

* `NumOutgoing=`

*Can be used with comparison operators* `=` , `<`, `<=`, `>`, *and* `>=`.

{% hint style="success" %}
`NumOutgoing<5`

Returns entities with fewer than 5 outgoing transitions.
{% endhint %}

### Second-order predicates

* `HasDirectTrace: sub-query`

Returns entities upstream and downstream from entities matched by the sub-query, including all hops by default. Use `Depth=` in the sub-query to limit the number of hops (e.g., `Depth=3` returns entities within 3 hops).

{% hint style="success" %}
`HasDirectTrace:(Name="Notional")`

Returns entities upstream and downstream (including all "hops") from any entity with the exact name *Notional*.

`HasDirectTrace: (Property: "DQ Score"="Fail" Depth=3)`

Returns entities within 3 hops upstream and downstream from any entity that has the property *DQ score* with the value *Fail*.

`HasDirectTrace: (HasDirectRelationship: (Label="is CDE"))`

Returns entities upstream and downstream (including all "hops") from any entity with a relationship labeled *is CDE*.
{% endhint %}

***

* `HasDirectTraceTo: sub-query`

Returns entities upstream from entities matched by the sub-query, including all hops by default. Use `Depth=` in the sub-query to limit the number of hops (e.g., `Depth=3` returns entities within 3 hops).

{% hint style="success" %}
`HasDirectTraceTo: (Property: "DQ Score"="Fail" Depth=3)`

Returns entities within 3 hops upstream from any entity that has the property *DQ score* with the value *Fail*.

`HasDirectTraceTo: (HasDirectRelationship: (Label="is CDE"))`

Returns entities upstream only (including all "hops") from any entity with a relationship labeled *is CDE*.
{% endhint %}

***

* `HasDirectTraceFrom: sub-query`

Returns entities downstream from entities matched by the sub-query, including all hops by default. Use `Depth=` in the sub-query to limit the number of hops (e.g., `Depth=3` retrieves entities within 3 hops).

{% hint style="success" %}
`HasDirectTrace: (Property: "DQ Score"="Fail" Depth=3)`

Returns entities within 3 hops downstream from any entity that has the property *DQ score* with the value *Fail*.

`HasDirectTrace: (HasDirectRelationship: (Label="is CDE"))`

Returns entities downstream only (including all "hops") from any entity with a relationship that has the label *is CDE*.
{% endhint %}

***

* `TransitionFrom: sub-query` (Alias `HasSource:`)

Returns transitions whose source entity matches the sub-query.

{% hint style="success" %}
`TransitionFrom: (Property: "DQ Score"="Fail")`

Returns transitions whose source entity has a *DQ Score* property equal to *Fail*.

`HasIncoming: (TransitionFrom: (HasDirectrelationship: Label="is CDE"))`

Returns entities with an incoming transition from an entity with a reference relationship labeled `is CDE`.
{% endhint %}

***

* `TransitionTo: sub-query` (Alias `HasTarget:`)

Returns transitions whose target entity matches the sub-query.

{% hint style="success" %}
`TransitionTo: (Property: "DQ Score"="Fail")`

Returns transitions whose target entity has a *DQ Score* property equal to *Fail*.

`HasOutgoing: TransitionTo: (HasDirectRelationship: (Label="is CDE"))`

Returns entities with an outgoing transition to an entity with a reference relationship labeled `is CDE`.
{% endhint %}

***

* `HasTransition: sub-query`

Returns entities with transitions matched by the sub-query. Transitions in the sub-query can be matched by source entity (using `HasSource:`), target entity (using `HasTarget:`), entity ID, property, relationship, and model.

* Note that when `TransitionFrom:` is used in the sub-query, `HasTransition:` only matches entities with incoming transitions from entities matched by the sub-query.
* Similarly, when `TransitionTo:` is used in the sub-query, `HasTransition:` only matches entities with outgoing transitions to entities matched by the sub-query.

{% hint style="success" %}
`HasTransition: (Property: "Type"="SQL parsing")`

Returns entities with an incoming or outgoing transition whose *Type* property is exactly *SQL parsing*.

`HasTransition: (TransitionFrom: (Property: "DQ Result"="Fail"))`

Returns entities with an incoming transition from entities whose *DQ Result* property is exactly *Fail*.
{% endhint %}

***

* `HasIncoming: sub-query`

Returns entities with incoming transitions matched by the sub-query. Transitions in the sub-query can be matched by source entity (using `TransitionFrom:`), target entity (using `TransitionTo:`), entity ID, property, relationship, and model.

* Note that `TransitionFrom:` can used in the sub-query to match entities that are the target of an incoming transition from entities matched by the sub-query.
* When `TransitionTo:` is used in the sub-query, `HasIncoming:` returns all entities matched by the sub-query that have at least one incoming transition.

{% hint style="success" %}
`HasIncoming: (Property: "Type"="SQL parsing")`

Returns entities that are the target of an incoming transition whose *Type* property is exactly *SQL parsing*.

`HasIncoming: (TransitionFrom: (Property: "DQ Result"="Fail"))`

Returns entities with an incoming transition from entities whose *DQ Result* property is exactly *Fail*.
{% endhint %}

***

* `HasOutgoing: sub-query`

Returns entities with outgoing transitions matched by the sub-query. Transitions in the sub-query can be matched by source entity (using `TransitionFrom:`), target entity (using `TransitionTo:`), entity ID, property, relationship, and model.

* Note that `TransitionTo:` can be used in the sub-query to match entities that are the source of an outgoing transition to entities matched by the sub-query.
* When `TransitionFrom:` is used in the sub-query, `HasOutgoing:` returns entities matched by the sub-query that have at least one outgoing transition.

{% hint style="success" %}
`HasOutgoing: (Property: "Type"="SQL parsing")`

Returns entities that are the source of an outgoing transition whose *Type* property is exactly *SQL parsing*.

`HasOutgoing: (TransitionTo: (Property: "DQ Result"="Fail"))`

Returns entities with an outgoing transition to entities whose *DQ Result* property is exactly *Fail*.
{% endhint %}

***

* `HasRelationship: sub-query`

`HasRelationship:` returns entities related to terms **and descendants (children, children of children, etc.) of terms** matched by the sub-query.

The predicates you can use in a `HasRelationship` sub-query to match reference relationships are:

* `Term=` (Alias of `Name=`) – The Reference term an entity is related to
* `Label=` – The label a relationship has
* `TermProperty:` (Alias of `Property:`) – The property of a Reference term an entity is related to
* `TermType=` (Alias of `EntityType=`) – The type of model entity a Reference term is
* `TermId=` (Alias of `EntityId`) – The ID of a Reference term
* `Model=` – The model a related Reference term is in

*Notes:* `Label=` *can be used alone or in conjunction with another predicate. You can use relationship-specific aliases or non-alias predicates in a relationship query.*

{% hint style="success" %}
`HasRelationship: Term=CDE`

Returns all entities related to the term *CDE* or to descendants of the term *CDE*.

`HasRelationship: Label="is part of" and TermProperty: Owner="Jack Russell"`

Returns entities with relationships labelled *is part of* to terms or descendants of terms whose *Owner* property is exactly *Jack Russell*.
{% endhint %}

***

* `HasDirectRelationship: sub-query`

`HasDirectRelationship:` returns entities related only to terms matched by the sub-query, not including entities related to descendants of terms.

The predicates you can use in a `HasDirectRelationship:` query to identify relationships are:

* `Term=` (Alias of `Name=`) – The Reference term an entity is related to
* `Label=` – The label a relationship has
* `TermProperty:` (Alias of `Property:`) – The property of a Reference term an entity is related to
* `TermType=` (Alias of `EntityType=`) – The type of model entity a Reference term is
* `TermId=` (Alias of `EntityId`) – The ID of a Reference term
* `Model=` – The model a related Reference term is in

*Notes:* `Label=` *can be used alone or in conjunction with another predicate. You can use relationship-specific aliases or non-alias predicates in a relationship query.*

{% hint style="success" %}
`HasDirectRelationship: Term=CDE`

Returns all entities related to the term *CDE*, excluding entities related to descendants of the term *CDE*.

`HasDirectRelationship: Label="is part of" and Property: Owner="Jack Russell"`

Returns entities with reference relationships labelled ***is part of*** to terms whose *Owner* property is exactly *Jack Russell*.
{% endhint %}

***

* `HasParent: sub-query` (Alias `ChildOf:`)

Returns immediate child entities of any entity matched by the subquery.

{% hint style="success" %}
`HasParent: Property: DataQuality=Pass` or `ChildOf: Property: DataQuality=Pass`

Returns the immediate child entities of entities whose *DataQuality* property is exactly *Pass*.
{% endhint %}

***

* `HasAncestor: sub-query` (Alias `DescendantOf:`)

Returns all descendants (children, children of children, etc.) of any entity matched by the subquery.

{% hint style="success" %}
`HasAncestor: Property: DataQuality=Pass` or `DescendantOf: Property: DataQuality=Pass`

Returns all descendants of entities whose *DataQuality* property is exactly *Pass*.
{% endhint %}

***

* `HasChild: sub-query` (Alias `ParentOf:`)

Returns the immediate parent of any entities matched by the subquery.

{% hint style="success" %}
`HasChild: Property: DataQuality=Pass` or `ParentOf: Property: DataQuality=Pass`

Returns the immediate parent of any entity whose *DataQuality* property is exactly *Pass*.
{% endhint %}

***

* `HasDescendant: sub-query` (Alias `AncestorOf:`)

Returns all ancestors (parents, parents of parents, etc.) of any entity matched by the subquery.

{% hint style="success" %}
`HasDescendant: Property: DataQuality=Pass` or `AncestorOf: Property: DataQuality=Pass`

Returns all ancestors of entities whose *DataQuality* property is exactly *Pass*.
{% endhint %}

## Syntax

Predicates can follow several syntax formats.

**First-order predicate syntax**

* `Predicate=value` (e.g., `Name="Interest Rate"`, `EntityType=Attribute`)
* `Predicate: key=value` (e.g., `Property: "Business Name"="Special Terms Period"`)

**Second-order predicate syntax**

* `Predicate: sub-query` (e.g., `HasRelationship: Label="is controlled by"` , `HasDirectTrace: HasAncestor: Property: "DQ Rule"="Accurate Amount"`)

Second-order predicates can be used in sub-queries:

For example, `HasAncestor: (Not HasDirectRelationship: Term="Notional")`

**Match multiple values using commas**

You can retrieve multiple values for the same predicate using commas to separate values:

* `Property: DataType=numeric, varchar, string`
* `HasRelationship: Term=Notional, Currency, Index`.

{% hint style="warning" %}
Commas have an “**Or**” logical function, so to query for the intersection of multiple values for the same predicate, you must repeat the predicate and use the operator “**And**” .

For example, the query `(HasRelationship: Label="is controlled by", "CDE")` retrieves entities with a relationship labeled “is controlled by” **OR** a relationship labeled “CDE”.

To query for entities with a relationship labeled “is controlled by” **AND** a relationship labeled “CDE”, use `(HasRelationship: Label="is controlled by") And (HasRelationship: Label="CDE")`.
{% endhint %}

**Query multi-select property values**

To query values for multi-select property types, you must use the contains `~=` comparison operator in a `Property:` query. This matches entities with **any** of the provided values (separate multiple values with commas).

**Example 1**

`Property: "multi"~="one", "two", "three"`

To query only entities with a specific combination of multi-select values, use the contains `~=` comparison operator and combine multiple property predicates using **And**.

**Example 2**

`Property: "multi"~="one" And Property: "multi"~="two" And Property: "multi"~="three"`

This query matches entities with the specific combination of values `one`, `two`, and `three` for the multi-select property `multi` .

To query only entities one or another specific combination of multi-select values, use the contains `~=` and separate combination statements with **Or**.

**Example 3**

`(Property: "multi"~="one" And Property: "multi"~="two") Or (Property: "multi"~="one" And "multi"~="three")`

This query matches entities with either `one` and `two` **or** `one` and `three` values for the multi-select property `multi` .

**Function of characters in query syntax**

Components of query syntax such as double quotation marks `"..."`, comparison operators `=`, the colon `:`, commas `,`, and parentheses `()` have the same function across different predicates.

* `"..."` - Non-directive quotation marks ensure the correct processing of special characters or spaces in multi-word phrases. They can also be used to indicate an empty value. *They are only required if query values contain special characters or spaces.*
* `:` - The colon separates a predicate from a key, such as a property name, or from another predicate, as in `HasAncestor: Name=System`.
* `,` - Commas can be used to separate multiple values for the same predicate. *Note: commas have an “Or” logical function, meaning the query will retrieve entities with any one of the provided values*.
* `()` - Parentheses are optional for single predicate queries, but they ensure correct grouping of predicates in complex queries and are required when using more than one distinct logical operator in a query.

Quotation marks can be used to retrieve entities that do not have any value for a property (i.e., the value is empty).

For example, `Property: DataQuality=Pass, ""` returns entities that have the property DataQuality with values “Pass” or with no assigned value.

### Logical operator syntax

Complex queries combine predicates using logical operators `And`, `Or`, or `Not` to express fine-grained conditions entities must satisfy.

There are two important rules to keep in mind when using logical operators:

* **All logical operators are case-sensitive:** they must start with a capital letter followed by lower-case letters.
* When no logical operator is provided between predicates, the condition is interpreted as **And**.

**Examples**

`Name=Customer Property: "Business Name" Property: DQscore=60` returns entities named “Customer” **and** with the property “Business Name” **and** the property “DQscore” with a value of 60.

Parentheses are not necessary for queries that use only one logical operator, but they generally improve readability:

`(Name=Customer) (Property: "Business Name") (Property: DQscore=60)`.

### Parentheses with logical operators

Parentheses **must** be used when two or more distinct logical operators are used in order to group predicates correctly to create a logical statement. The placement of parentheses determines which predicates logical operators apply to.

**Grouping using parentheses**

Let's look at an example where parentheses are not used in a query with more than one unique logical operator:

`Name=CDE And Property: DataQuality=Pass Or Property: "DQ Dimension"=Validity`

This is not a valid query because it is not possible to determine how the predicates should be grouped. The query could be interpreted in two ways:

* `(Name=CDE And Property: DataQuality=Pass) Or Property: "DQ Dimension"=Validity`

Returns entities named *CDE* whose *DataQuality* property is exactly *Pass* and entities whose *DQ Dimension* is exactly *Validity*.

* `Name=CDE And (Property: DataQuality=Pass Or Property: "DQ Dimension"=Validity)`

Returns entities named *CDE* whose *DataQuality* property is exactly *Pass* and entities named *CDE* whose *DQ Dimension* property is exactly *Validity.*

**Examples of Not syntax with parentheses**

When adding a `Not` operator using the query helper, the operator is automatically added inside parentheses, `(Not )`, to ensure the negation is applied only to predicates included in the parentheses.

* `(Not Name=CDE) Property: DataQuality=Pass Or Property: "DQ Dimension"=Validity`

This returns entities **not** named *CDE* whose *DataQuality* property is exactly *Pass* **or** whose *DQ Dimension* property is exactly *Validity*.

* `(Not Name=CDE Or Property: DataQuality=Pass) Property: "DQ Dimension"=Validity`

This returns entities whose *DQ Dimension* property is exactly *Validity*, but NOT those either named *CDE* or whose *DataQuality* property is exactly *Pass*.

### Parentheses with second-order predicates

Second-order predicates require a sub-query that nests first- or second-order predicates inside them. While not always required, it is often better to add parentheses around the sub-query to make it more readable.

{% hint style="success" %}
`HasRelationship: (Term=Customer And Property: DataQuality=Pass)`

Returns entities related to a term, or descendants of a term, *Customer* that has a value *Pass* for the property *DataQuality*.
{% endhint %}

Using parentheses to group predicates in subqueries ensures query conditions are correct.

{% hint style="success" %}
Compare this example to the previous example

> `HasRelationship: (Term=Customer) And (Property: DataQuality=Pass)`

Returns entities that have a value *Pass* for the property *DataQuality* and are related to the term or descendants of the term *Customer* .
{% endhint %}

## Example queries

Questions or search objectives formulated in natural language can be translated into queries. Here is a list of example queries followed by their natural language equivalents.

{% hint style="success" %}
Quotation marks are only required when the values you are querying contain spaces or special characters.
{% endhint %}

* `ModelId: 667bf339652d59b49703fb10 And Property: DQscore=pass`

Find all entities in a particular model that have the property *DQscore* with the value *Pass*.

* `Property: DQscore=Pass,"Not Pass"`

Find all entities with the property *DataQuality* that have values *Pass* or *Not Pass*.

* `Name=System And (Not Property: DQscore=Pass)`

Find all entities named *System* that do not have the property *DQscore* with a value exactly equal to *Pass*.

* `Property: DQscore!=pass, fail` (equivalent to `Not Property DQscore=pass, fail`)

Find all entities that do not have the property *DQscore* with values *pass* or *fail*.

* `Property: DQscore=""`

Find all entities that have the property *DQscore* with no assigned value.

* `Not (Property: score Property: "Data quality" Property: "Business name")`

Find all entities that do **not** have all three properties *score* AND *Data quality* AND *Business name*.

* `Model="Banking Template Lineage Model","Template EUC" And EntityType=Attribute And (Not HasDirectRelationship: Label="is controlled by")`

Find entities in either the *Banking Template Lineage Model* OR the *Template EUC* model that are Attributes and do **not** have a relationship with the label *is controlled by*.

* `HasDirectTraceFrom: (HasDirectRelationship: (Label="PII" (Term="first name", "last name", "mother maiden name")))`

Find all entities downstream from entities with reference relationships labeled *PII* to the terms *first name*, *last name*, or *mother maiden name*.

* `HasDirectTraceFrom: (HasRelationship: (Label="PII" Term="personal identifiable information"))`

Find all entities downstream from entities with reference relationships labeled *PII* to the term, or descendants of the term, *personal identifiable information*.

* `HasRelationship: (Term=Mortgages Model="Product Reference Model") And HasRelationship: (Term="Mr X" Model="Data Owners Reference Model")`

Find entities related to the term, or descendants of the term, *Mortgages* in the *Product Reference Model* AND to the term, or descendants of the term, *Mr X* in the *Data Owners Reference Model*.

* `HasRelationship: (Term=PII Model="Master Data Governance" TermProperty: Critical=Yes)`

Find all entities related to the term *PII* in the model *Master Data Governance* whose *Critical* property equals *Yes*.

* `EntityType=Attribute And NumIncoming>1`

Find all Attributes with more than one incoming transition.

* `HasIncoming: TransitionFrom: Property: "DQ Result"=Fail`

Find all entities with an incoming transition whose source entity has the property *DQ Result* equal to *Fail*.

* `TransitionFrom: HasParent: Name="Core Banking System" And TransitionTo: HasParent:Name="SED"`

Find transitions whose source is a child of *Core Banking System* and whose target is a child of *SED*
