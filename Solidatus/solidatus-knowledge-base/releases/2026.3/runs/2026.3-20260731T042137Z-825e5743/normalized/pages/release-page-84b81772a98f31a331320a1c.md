# Grid reports

Grid reports are customisable exports of data stored in a model in CSV or JSON formats. Grid reports offer a useful way of preparing model data for analysis in external tools or bulk editing model data to [reimport it back into the model](/models/build-and-edit-models/export-and-reimport-to-edit-model-content).

Several reports are automatically included with every model (they cannot be removed or edited, but they can be duplicated).

Grid reports are saved when a model is saved, and they are stored in [model revisions](/models/build-and-edit-models/version-control).

{% hint style="warning" %}
After creating and editing reports, you have to save the model to keep your changes.
{% endhint %}

### What is a grid report?

A grid report is a customisable tabular or JSON export of data stored in a model. In tabular exports, each row in the report represents an entity in the model that matches the criteria chosen to include in the report, and each column corresponds to a specific characteristic of that entity.

Column values and column labels can be customised in the report. Each column value is defined using a query expression that specifies what data to include in that column. Column labels can be customised to provide meaning for the data presented.

See the [Query expressions for column values](#query-expressions-for-column-values) section for a list of available expressions that can be used to define column values.

{% hint style="success" %}
If you include columns for transitions or reference relationships in a report, multiple rows might represent the same entity - one row for each of its transitions or relationships.
{% endhint %}

### Create a report

To access grid reports, select **Reports** in the [Model Viewer toolbar](/the-user-interface/models-ui/model-viewer#the-model-viewer-toolbar).

<figure>The list of reports available within a model<figcaption><p>The list of reports available within a model</p></figcaption></figure>

The top four entries in the list above cannot be edited or deleted - these are the default reports.

From this dialog, you can create a new grid report, edit an existing report, or duplicate an existing report and then edit it.

Custom reports can be:

* **Created** : Click **Create new report** to open the report editor and define a new report
* **Opened** : Select the name of a report to preview its contents and download a CSV or JSON file
* **Edited** : Rename the report or redefine entities, column values, and column names
* **Duplicated** : Duplicate a report to build a new report based on an existing one
* **Deleted** : Remove a report from the list

{% hint style="warning" %}
Changes to grid reports are not saved until the model is saved as a new revision.
{% endhint %}

### Define a grid report

Each grid report consists of the following elements:

> 1. The name of the report
> 2. An optional description of the report
> 3. The entities to include in the report, which make up the rows in a tabular export (see [Specify entities (rows) in a report](#specify-entities-rows-in-a-report))
> 4. The column values and column labels in the report (see [Specify column values and labels](#specify-column-values-and-labels))

<figure>A report showing details of Attributes in a given Layer<figcaption><p>A report showing details of Attributes in a given Layer</p></figcaption></figure>

The **Entities (rows)** selection and the **Columns** selection are the key elements of a report. They determine what data is included and how it is presented.

### Specify entities (rows) in a report

The entities that populate the rows of a report are specified in the **Entities (rows)** section of the report editor.

You can include the entire model, but you probably want to filter the entities that you include, unless you have a very simple model. The report editor allows you to choose from the following prepopulated filtering options:

> * All entities (the default)
> * the currently selected entities (you can then add a query to further filter the selection)
> * All Layers
> * All Objects
> * All Attributes
> * All Transitions
> * Entities matching a query

To define entities to include in the report:

1. Select the dropdown next to the **Entities (rows)** section
2. Choose one of the prepopulated options, or choose **Query** to specify entities using a query in the [Model Query Language](/models/explore-and-analyse-models/model-query-language)
3. If you choose one of the prepopulated options, you can move on to the **Columns** section
4. If you choose **Query**, you must enter a query in the query field that appears.

{% hint style="success" %}
If you choose **selected entities**, the report will include only those entities that are selected when you opened **Grid reports** from the toolbar. You can also add a query to further filter the selection.
{% endhint %}

When you enter a query, matching entities are included in the report. You can use any valid query expression in [Model Query Language](/models/explore-and-analyse-models/model-query-language).

## Specify column values and labels

There are no default columns in a new report. You must choose data to include in a column by selecting the *Column value* field and selecting a query expression from the dropdown menu (or typing it). Then you must type a heading for the column in the *Column label* field.

<figure>Entering report columns<figcaption><p>Entering report columns</p></figcaption></figure>

### Column data

The data included in a columns are defined using query expressions similar to those used in [Model Query Language](/models/explore-and-analyse-models/model-query-language). The query expression retrives corresponding data for each entity included in the report.

If an entity does not have data corresponding to the query expression, the column will be blank for that entity. If an entity has multiple values corresponding to the query expression, multiple rows will be created for that entity - one for each value (e.g., if an entity has three incoming transitions, three rows will be created for that entity if you include a column with the value `$incoming`).

The [Query expressions for column values](#query-expressions-for-column-values) section below gives a complete list of available expressions and descriptions of what they do.

You can, and in some cases must, [chain expressions together](#chain-query-expressions-for-column-values) to retrieve specific entity data for column values.

### Column labels

You can enter any text you like as a column label. The label appears as the column heading in tabular exports and as the value for the `"label"` key in the columns array in JSON exports.

If you do not supply a label, the query expression in the corresponding *Column value* field is used as the column label in tabular exports, and JSON exports do not include a `"label"` key.

### Entity selection and column data combination

The data retrieved in a column depends on both the entities included in the report (the rows) and the query expression that defines the column value.

Some query expressions do not return data for certain entity types. For example, if you include layers in a report, the expression `$object` does not return data because layers are not objects. Similarly, the expression `$parent` does not return data for layers or transitions.

Column fields are empty for included entities that do not have data corresponding to the query expression.

When constructing query expressions to define column values, consider the types of entities included in the report and the relations of entity types in a model.

## Chain query expressions for column values

When defining columns in grid reports, you can chain expressions together to target the precise value you want to retrieve.

Chained values use dot notation, where expressions are linked together using a full stop – if you type `.` after an expression, an auto-complete list of expressions available to chain appears.

For example, type `$relationships.` to list expressions appropriate to relationships.

### An example of chaining

You might want a column with names of entities linked to a given entity via transitions. The following model provides a simple illustration, where we want to report on entities linked to the object *Entity in report row* in the middle Layer.

Let’s say you want to include the object name for incoming transitions and the entity name for outgoing Transitions.

<figure>A simple model with Transitions<figcaption><p>A simple model with Transitions</p></figcaption></figure>

To achieve this, we have to use a query to include only the object in the middle layer in the report. There are several queries that could do this:

> 1. specify the name of the entity
>
>    > `$name="Entity in report row"`
> 2. specify the exact type, name and location of the Entity
>
>    > `isObject() and $name="Entity in report row" and $layer.$name="Selected"`
> 3. specify part of the Entity name
>
>    > `contains($name,"report row")`
> 4. specify the current selection (with an optional query to provide more filtering)

Which approach you take will depend on your specific requirements.

> * If you want other users to be able to run your report without pre-selecting entities, and you know the model is stable, the first option might be right for you. This option will only ever report on the chosen entity BUT, will stop working if the entity or the layer are renamed, or the entity is moved further down the hierarchy, and is no longer an object.
> * If you’re happy to include every entity with “report row” in the name, perhaps the third option works for you.
> * If you want a generic report that will provide information on whatever you select, the third option is the one for you. If you want to filter selected entities (e.g. only report on Objects), you can also add a query (such as `isObject()`) .

In the report definition, we would include the following columns:

| `$name`                           | The name of matched entities (here, the object in the report row)                                                                                                                                                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `$incoming.$source.$object.$name` | <p>The names of the Objects that are the source of incoming transitions;</p><p>if the source Entity is a Group or Attribute, this will return the name of the <strong>Object</strong> that owns it;</p><p>if the source Entity is a Layer, <strong>nothing</strong> is returned.</p> |
| `$outgoing.$target.$name`         | The names of all entities that are the target of outgoing Transitions                                                                                                                                                                                                                |

The report output contains one row for every combination of entities encountered:

<figure>The report content<figcaption><p>The report content</p></figcaption></figure>

{% hint style="success" %}
Reports involving transitions and reference relationships often contain multiple rows for an entity. A distinct row is created for each of an entity’s [transitions](/models/build-and-edit-models/add-and-edit-entities#add-transitions) or [reference relationships](/models/build-and-edit-models/add-and-edit-reference-relationships). There could be **10 rows** for an entity, for example if it has five incoming transitions and five reference relationships.
{% endhint %}

## Preview and export a report

The quickest way to view the output from a report is to click the list button next to `Reports` in the [Model Viewer toolbar](/the-user-interface/models-ui/model-viewer/model-viewer-toolbar) then click on the name of the report.

<figure><figcaption><p>The list of reports is available directly in the toolbar</p></figcaption></figure>

Alternatively, you can open the grid reports editor and select the name of a report to preview and export its contents.

<figure>Export your grid report in CSV or JSON<figcaption><p>Export your grid report in CSV or JSON</p></figcaption></figure>

Click **Export CSV** or **Export JSON** buttons to download a file containing CSV or JSON data respectively.

{% hint style="success" %}
The data in a grid report is updated each time the preview of the report is loaded.
{% endhint %}
