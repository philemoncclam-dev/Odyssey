# Add and edit properties

**Properties** store additional information — technical, descriptive, conceptual — that classifies, describes, and identifies an entity in a model.

A property consists of a **property type**, a **property name** and a **property value.** The property name is also referred to as its key, and so a property consists of a **key:value** pair.

For general information about properties, visit [Understand Properties](/models/understand-solidatus-models/understand-properties) and [Property Types.](/models/understand-solidatus-models/understand-properties/property-types)

## Assign properties to an entity

Through the user interface, you can only assign a property to an entity in the `Properties and Relationships section` in the [Model Viewer Sidebar](/the-user-interface/models-ui/model-viewer/model-viewer-sidebar).

Assigning a property to an Entity is simple: There’s an empty entry at the foot of the list of properties - where it says *Add new property* - ready for you to assign an existing property and provide a value, or [create a new property](#how-to-create-a-new-property-and-assign-a-value).

<figure><figcaption><p>Assign existing property to an Entity</p></figcaption></figure>

### **Assign an existing property**

To assign an existing property to a single entity:

* Select where it says `Add new property` to pick an existing property from the drop-down list; if the list is too long to scroll through, type a few characters to filter the list - the list will only contain properties that are not already assigned to this entity.
* Select the name of your chosen property, then choose or enter a value for the property. How you do this will vary depending on the property type (see [Characteristics of property types](/models/understand-solidatus-models/understand-properties/property-types)).
* If you don’t wish to provide a value for the property yet, just click on another property.

## Assign a property to multiple entities

Adding properties to multiple entities can be useful and time saving. All you need to do is to select multiple Entities then proceed as described in [Assign an existing property to an Entity](#assign-an-existing-property),

To select a range of entities:

> * Click the first entity to select it
> * `Shift` + click the last entity to select all entities up to this one

To select multiple ranges of entities:

> * Click the first entity
> * `Shift` + click the last entity to select all entities in this range
> * `Ctrl` + click the first entity in the second range
> * `Shift` + click the last entity in the second range

## Edit assigned property values

You can only change the assigned value(s) of a property in the `Properties and Relationships` section in the [Model Viewer Sidebar](/the-user-interface/models-ui/model-viewer/model-viewer-sidebar). How you do this will vary depending on the property type (see [Characteristics of property types](/models/understand-solidatus-models/understand-properties/property-types)).

{% hint style="warning" %}
You cannot edit the properties of [entities that have been imported](#import-properties).
{% endhint %}

If you want to change the assigned value for multiple entities you will need to select them first - see [Assign a property to multiple Entities](#assign-a-property-to-multiple-entities).

{% hint style="success" %}
If you want to change all occurrences of a property value (e.g. change all occurrences of *Finished* to *Complete*) the best way to achieve this is to use the [Property Manager](#the-property-manager), which also allows you to merge two values.
{% endhint %}

## Create a new property and assign a value

If the property you need does not exist yet, you can create it in the `Properties and Relationships` section in the [Model Viewer Sidebar](/the-user-interface/models-ui/model-viewer/model-viewer-sidebar) or in the [Property Manager](#the-property-manager).

To create a property in the `Properties and Relationships` section, you will need to provide the type, name (or key), and at least one value to be assigned to the selected entity (or entities). In the [Property Manager](#the-property-manager) you do not need to provide a value, and the property type will always default to *Text*.

## The Property Manager

The Property Manager is the control panel for all properties within a Model. It allows you to:

> * See all properties and their values
> * Examine the values for all text properties and infer the appropriate property type
> * Define a new property
> * Rename a property or edit individual values (automatically updating all affected Entities)
> * Delete an entire property or individual values
> * Merge properties (e.g. merge **Data Type** and **Data\_Type**)
> * Merge property values (e.g. merge **true** and **yes** into **Y**)
> * Find all Entities with a given property
> * Find all Entities with a given value for a given property

In order to gain access to Property Manager, you must open the Properties sidebar (press the `p` key) and click on the **Manage all properties** button. If you have the Model open in read-only mode, click on the **View all properties** button.

The Property Manager dialogue shows the number of properties defined and, for each defined property, the number of different values for that property, and the total number of times the property has been assigned within the model. In addition, there is a search bar to filter the list of properties (ideal if you have a lot of properties), a drop-down list of sorting options, a green button to define a new property, and a button to Export the properties and their values to a CSV file.

By default, the list is sorted with the *most used* properties at the top. You can use the `Sort` dropdown to show them in a different sequence, such as alphabetical (the folder name is regarded as part of the property name, so `Population %` will be listed above `Text/Description`).

## Infer property types

Imagine you have a Model where all the properties are text properties, and you would like to start using property types. For example, here is a set of text properties where the property name matches the existing value for each property.

<figure><figcaption><p>Text properties <strong>before</strong> inferring property types</p></figcaption></figure>

When I click on the `Infer Types` button, Solidatus will examine the values of all the *Text* properties and assign a property type that matches all of the current values.

**For example:**

* if the property has the values ‘1’, ‘2’ and ‘3’ we will infer that type to be a number
* if instead the values are ‘one’, ‘2’ and ‘3’, not all the values are valid numbers so it remains as a text type
* if the values are within quotes and surrounded by square brackets (e.g. `["value1"]` or `["value1", "value2"]`) we will infer that type as a multi-select.

Solidatus will not assign a property type if any of the current values does not match that type - it will not result in any invalid values.

## Remove properties from a model

Unused properties will remain in the Model until they are removed. To remove a property from the Model, select the *Remove* icon to the right of the property name in the [Property Manager](#the-property-manager). A confirmation message will be displayed, advising you of the number of Entities affected by removing the property. Click `Delete` to finish.

{% hint style="success" %}
See also [Import Properties](#import-properties)
{% endhint %}

## Rename a property

To rename a property, click on the pencil icon to the right of the property name, type the new name and then click on either `Save` or `Save and update queries`. If you change your mind, click `Cancel`.

{% hint style="danger" %}
If the new property name matches the name of another property, [the two properties will be merged](#merge-property-values).
{% endhint %}

<figure><figcaption><p>Renaming a property in the Property Manager</p></figcaption></figure>

All assignments of the property will be updated to reflect the new name.

If you know (or just think you know) that a property is used in any Filters or Display Rules, make sure you click on `Save and update queries` to ensure that they are updated to reflect the new property name. If you don’t do this some of your Filters and Display Rules might stop working.

{% hint style="warning" %}
This is the only way to rename a property. You cannot rename a property in the [Properties and Relationships section](/the-user-interface/models-ui/model-viewer/model-viewer-sidebar/the-inspector-tab#the-properties-and-relationships-panel) in the [Model Viewer Sidebar](/the-user-interface/models-ui/model-viewer/model-viewer-sidebar), as this creates a **new** property; it does **not** rename the existing property.
{% endhint %}

{% hint style="success" %}
Sometimes when you rename a property, the result might be two properties instead of one.

This will only happen if you have imported content from a model that has a property with the exact same name as a property in the current model. You cannot rename a property for imported content - if the two models need to have identical property names, both models will need to be updated.
{% endhint %}

{% hint style="danger" %}
You cannot rename or delete properties of imported entities. You will notice that for imported entities, the pencil (rename) and waste bin (delete) icons are not available in the Property Manager.
{% endhint %}

## Merge properties

Two existing properties can be merged into a single property by renaming one property so that it matches the name of the other property - remember, property names are case sensitive so the match must be exact.

For example, assume there are two existing properties with similar names - **Status** and **Review Status**, which we’d like to merge.

We can rename either of the two properties to match the other - before deciding which one to rename, we should consider any differences in the property type.

* If the property types are different, this is how they are resolved:

| **From** (Property being renamed) | **To** (Matching Property) | **Result**   |
| --------------------------------- | -------------------------- | ------------ |
| Select                            | Multi-select               | Multi-select |
| *Other type*                      | Text                       |              |
| Multi-select                      | Select                     | Multi-select |
| *Other type*                      | Text                       |              |
| *Other type*                      | Select                     | Select       |
| Multi-select                      | Multi-select               |              |
| *Same type*                       | *No change*                |              |
| *Any other combination*           | Text                       |              |

The property values are copied across from the renamed property to the matching property. This might result in some existing values of the matched property being flagged as invalid.

**For example, here are the properties mentioned before:**

* **Status** (property type = *Select*)
* **Review Status** (property type = *Checkbox*).

I suspect the *Review Status* is only assigned to Entities that have passed or failed a review - the modeller is now applying a more comprehensive (and more useful) set of values for this status, but they were a bit lazy with the property name and just called it *Status*. A colleague pointed out the existing *Review Status* and they decided to merge the two properties.

Looking at the two properties, they decided that the merged property should be called *Review Status* and the property type must be *Select*. One property has the right name, and the other one has the right values.

## View and edit property values

To examine the list of values for a property, click on the the property name or the number of values (highlighted in blue) to the right of the property name. A sortable list of existing values will then be displayed - by default, the properties with the most assignments appear at the top of the list.

<figure><figcaption></figcaption></figure>

* Click on the magnifying glass icon alongside a value to `search for Entities` with that value for the property - this will close the Property Manager dialogue, create the required query in the search bar in the Model Viewer, and focus the Model Viewer on the query results.
* Click on the pencil icon alongside a value to `amend a value`.

  > For example, let us assume that we want to replace the value **Low** with the value **One**. By changing the value **Low** to **One** and clicking **Save**, all of the entities with that property value will be updated.

{% hint style="success" %}
Editing a lengthy property value through the Property Manager can be difficult because you can only view one line of text at a time. If a property value is more than one line, search for an entity to which it is assigned and edit it via the Sidebar by clicking the `pencil icon` next to the property value.
{% endhint %}

* Click on the `remove value` icon alongside a value to `remove the value` and `remove the property` from all entities that have that property value assigned.

**Adding a new value**

If the property type is not *Number* or *Checkbox* you can add a new value by clicking on the green `Define value` button to `add a new value` to the list.

## Import properties

When you import content from another Model, the import will include properties that are assigned to the imported content. It will not include any properties that are either unused, or only assigned to content that has not been imported.

If an imported property has *exactly* the same name (including any folders) as an existing non-imported property the two properties are combined.

{% hint style="warning" %}
Property Types are ignored in imported content - all imported properties will either be set to *Text* type or will take on the type of an existing, matching, property (as described above).
{% endhint %}

When you delete all the content **imported** from another Model, any properties that are only assigned to that content will be removed when the Model is saved and you close the Model Viewer.

## Use markdown to format property values

You can use standard Markdown notation to format property values. Property values will show their formatted output in the `Properties and Relationships` panel.
