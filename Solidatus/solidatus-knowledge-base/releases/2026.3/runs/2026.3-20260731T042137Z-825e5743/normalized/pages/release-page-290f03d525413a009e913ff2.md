# Permissions

Our recommendation when creating users in the systems used by the Purview connector is to provision them with the minimum required permissions in order to perform their jobs.

## Solidatus User Permissions

The Purview connector will require a Solidatus API token in order to operate. These are the capabilities which the token needs to have in order to perform various functions.

| Capability   | Required | Reason                                                                                          |
| ------------ | -------- | ----------------------------------------------------------------------------------------------- |
| View Model   | Yes      | To read data from models in Solidatus in order to generate the data to send to Purview          |
| Create Model | No       | To write purview information (qualified name, Purview ID) back to the source model in Solidatus |

Further information on managing Solidatus Tokens can be found in the Solidatus help documentation under the `Connectors | Users and Token section`

## Purview User Permissions

Connecting to Purview requires the creation of an Azure Service Principal and granting that principal access to the appropriate Purview resources. The steps for doing so can be found in the Microsoft documentation here: <https://learn.microsoft.com/en-us/purview/tutorial-using-rest-apis>

The Azure Service Principle used by the connector requires the `Data Curator` role for read and write access to Domains and Collections in Purview.

The instructions for granting roles to the Azure Service Principle can be found on the Microsoft documentation here:

* Purview Governance Portal, <https://learn.microsoft.com/en-us/purview/how-to-create-and-manage-domains-collections>
* Purview (classic), <https://learn.microsoft.com/en-us/purview/how-to-create-and-manage-collections>

### Purview API Authentication

During the Azure Service Principle creation process you will create a client id and client secret. Make sure to note what that is, as it is required in the connector configuration. The full list of required Purview configuration items is as follows:

| Field                           | Example                                            | Description                                                                                        |
| ------------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Azure Purview API endpoint      | https\://{your-purview-account}.purview\.azure.com | URL of your Purview instance                                                                       |
| Azure Purview tenant id         | 12345678-1abc-2def-ba81-99999999999                | Tenant ID of your Purview instance. Can be found in the URL after logging in to the Purview web UI |
| Azure Purview client id         | 12345678-1abc-2def-ba81-99999999999                | Client ID of the Service Principal you created for access to Purview                               |
| Azure Purview client secret     | \*\*\*\*\*\*\*\*                                   | The secret created during the creation of the Service Principal                                    |
| Azure Purview API token scope   | `https://purview.azure.net/.default`               | The URI of the resource the token is acquired for, passed as `resource` to the token request       |
| Azure Purview API collection ID | abcdef                                             | ID of the collection to add/update assets in. If not set will use the default collection           |
